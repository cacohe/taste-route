# Render CD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Support Railway and Render from one container while automatically deploying the tested `main` commit to Render after CI succeeds.

**Architecture:** Platform files remain small adapters around the root Dockerfile. GitHub Actions is the release gate; Render's native commit auto-deploy is disabled and a protected deploy-hook job runs after the existing backend, frontend, and container jobs.

**Tech Stack:** GitHub Actions, Docker, Render Blueprint, Railway configuration, pytest, Vue 3/pnpm.

**Spec:** `docs/superpowers/specs/2026-10-28-render-cd-design.md`

## Global Constraints

- Maintain and deploy `main` only.
- Preserve `railway.json` and defer Railway CD.
- Never commit deploy hooks or provider credentials.
- Deploy exactly the commit that passed CI.

## Review Focus

- A pull request must not trigger deployment.
- A missing Render secret must produce an explicit safe skip, not an attempted empty request.
- A valid hook URL that already has a query string must receive an encoded `ref` parameter correctly.
- Render must not deploy a new commit before CI finishes.
- Railway and Render must use the same Docker image and health endpoint.
